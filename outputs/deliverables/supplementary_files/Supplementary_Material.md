## Supplementary Text S2. Rule provenance and verification

The verification report covers **8 manifest items spanning 7 distinct DOIs**. It establishes that
these records exist, are not retracted and match their titles; it does not establish that a record
supports a specific pair, route and severity. This revision therefore adds a structured audit of all
40 rules (Table S9), scoring each on three questions: does the source concern the named ophthalmic
agent, does it support the pair, and does it support the assigned severity and route.

The audit classifies 2 rules as direct ophthalmic pair evidence, 5 as contextual ophthalmic evidence,
23 as systemic-route class evidence extrapolated to the ophthalmic agent, and 10 as mechanism-only with
no pair-level clinical source. Severity is directly supported for 2 rules, inferred for 28 and
provisional for 10. "Citation-verified" in the manuscript therefore means what Table S9 records.

**Corrections made in this revision.** Four citations that named an unrelated drug were corrected.
`beta_blocker_digoxin_additive` cited Schuman 2000, a study of topical-plus-systemic beta-blockade
that does not address digoxin; the citation was removed, the rule now carries only its DDInter pair
record and is labelled class-extrapolated. `antibiotic_warfarin_enhancement` cited the timolol
DrugBank entry and now cites the warfarin monograph. `low_abs_antiplatelet` and
`low_abs_anticoagulant` cited latanoprost, a prostaglandin analogue; they are relabelled as
absorption priors rather than pair-level DDI evidence.

The report is bound to a SHA-256 of `configs/rules.yaml`, so any later edit invalidates it. The
verification report is deposited as `outputs/citation_verification_report.json`; the
rule-level audit is deposited as `data/curation/rule_provenance_audit.csv`.

## Supplementary Text S3. Evaluation prompts

Transcribed from `scripts/run_multiseed_per_dataset.py`, which is authoritative. The same file is deposited as `configs/prompts.yaml`.

**Model and decoding.** `deepseek-chat`; `max_tokens = 10`; five temperature conditions (0.0, 0.3, 0.6, 0.9, 1.2). The 10-token cap forces a one-word answer and precludes any reasoning or justification; this bound on the comparison is stated in the manuscript (Section 2.4) and in the deposit README.

**System prompt (all three LLM methods).**

```
You are a clinical pharmacologist assessing ophthalmic drug-drug interaction risk.

Classify the interaction risk as: low, medium, or high.
Definitions:
- low: negligible clinical significance at ophthalmic doses
- medium: potential interaction requiring monitoring or dose adjustment
- high: clinically significant interaction; may require avoidance or strict monitoring

Consider ophthalmic pharmacokinetics (systemic absorption from eye drops is often <10% of oral dose,
but some drugs like timolol, atropine, dexamethasone reach >50%).

Reply with EXACTLY ONE WORD: low, medium, or high. No explanation.
```

**Prompt caveat.** The configuration-1 `rule_context` baseline was re-run with corrected exposure bands (high >=10%, medium 1-10%, low <1%) and the absorption gate; its deposited predictions are in `outputs/multiseed_per_dataset_rulecontext_fix/`. `pure_llm` and `naive_rag` were not re-run and share the original system prompt, which lists dexamethasone as >50% after the tier was corrected to medium (1-10%, peak plasma <1 ng/mL; Tables S5b and S10). Configuration 2 `rule_context` uses the pre-correction prompt and is not directly comparable to the corrected configuration-1 value. The deterministic cascade is unaffected.

**User prompt — `pure_llm`** (no retrieved evidence):

```
Drug pair: ophthalmic {oph} (eye drops) + systemic {sysd} (oral/IV)
Risk level:
```

**User prompt — `naive_rag`** (BM25 retrieval over the same 1,307 evidence chunks: `BM25Okapi`, k1 = 1.5, b = 0.75, top-k = 3, each passage truncated to 400 characters):

```
Evidence:
{retrieved_passages}

Drug pair: ophthalmic {oph} (eye drops) + systemic {sysd} (oral/IV)
Risk level:
```

**User prompt — `lightrag`**: identical structure, with the context block generated by `PreciseKG.full_kg_context()` rather than by a query to the LightRAG vector index. The baseline is named `lightrag` for continuity with earlier protocol versions; the manuscript states this limitation explicitly (Section 2.4).

**Parsing.** Lowercase the response; `high` if it contains "high"; else `medium` if it contains "medium" or "moderate"; else `low` if it contains "low"; otherwise `unknown`. One of the 9,600 primary predictions (audit set, `naive_rag`, temperature 1.2) returned an unparseable string and was scored `unknown`; all others parsed. No reasoning-model sample returned `unknown`.

**Reasoning-model re-run (reported in Section 3.6 and Table 3 of the manuscript).** The three LLM baselines were re-run in configuration 2 with a reasoning model (3000-token allowance). All parameters, as requested:

| item | value |
|---|---|
| provider / endpoint | Zhipu coding-plan endpoint `https://open.bigmodel.cn/api/coding/paas/v4` |
| model identifier | `glm-5.3-flash` |
| temperature | 0.0 (fixed; five repeated samples per case) |
| max_tokens | 3000 |
| reasoning effort | not set — the request carries only `max_tokens` and `temperature`, so the endpoint default applied |
| reasoning tokens | count against the 3000-token budget (`reasoning_content` is emitted before `content`) |
| truncated responses | 0 of 3,150 (completion_tokens never reached max_tokens) |
| vote resolution | majority over the five samples; every case had at least three concordant samples, so no tie arose |
| per-sample parsing | exact match first, then substring `high` > `medium`/`moderate` > `low`, else `unknown`; no sample returned `unknown` |
| run dates | 23-24 September 2026 |
| raw responses | deposited in full: `data/predictions/glm53_baselines/predictions.jsonl` (3,150 rows with token usage) |
| run script | `scripts/rerun_glm53_baselines.py` |

Single-model caveat: this is one commercial reasoning model at one endpoint, and the endpoint exposes no checkpoint revision. The finding that reasoning models adopt a conservative rarely-high-risk policy is therefore a property of this model at this budget, not a claim about reasoning models in general. The deterministic cascade makes no model call and is identical under both settings.

## Supplementary Text S5. Evaluation reproducibility

- Five temperature conditions: 0.0, 0.3, 0.6, 0.9, 1.2
- Prediction rows: 9,600; API failures: 0
- SHA-256 fingerprints are defined over **LF-normalised content**; convert CRLF to LF before hashing or Windows and Linux checkouts will differ. Evaluated rules version: the current `configs/rules.yaml` (hash in `MANIFEST.sha256`).
- Statistical tests: exact McNemar, Wilson 95% CI, bootstrap CI for kappa, Clopper-Pearson for proportions
- Revision statistics: `scripts/revision_r1_stats.py` writes `outputs/recomputed/revision_r1_stats.json`, from which every number in Sections 3.3-3.6 and Tables 3 and 5 can be regenerated.

**Retrieval-scope audit (prospective, all methods).** Of the 1,307 evidence chunks, 500 are DDInter
2.0 severity statements, and the audit reference labels for the 62 third-party cases *are* the DDInter
values. Before comparing methods we measured, for each method, how often its context contains the
pair's own DDInter statement (Table S13). `naive_rag` (BM25 top-3) contains it for 26 of 92 cases
(28.3%); `pure_llm` has no retrieval channel and `rule_context` builds its context from the
registries and rule configuration rather than the 1,307-chunk corpus, so neither has a
DDInter-statement channel. Results with and without the 26 affected cases are reported for the
cascade in Table 5 and for all methods under configuration 1 in Table S13; the configuration-2
exclusion figures quoted in Section 3.6 appear in that section.

## Supplementary Text S8. Protocol detail

This section carries the parameter-level detail that Section 2 of the manuscript summarises.

**Audit-set correction deviations.** The stated correction rule was applied with three deviations. (i) Seven corrected cases (D3-048, D3-049, D3-057, D3-063, D3-078, D3-079, D3-081) are in fact reached by the engine through a mechanism rule and therefore fail the stated no-rule condition. (ii) The two aflibercept pairs, whose registry tier is `minimal_systemic_absorption` (recorded as `none` in the audit design file), were kept at DDInter severity although the stated rule would correct them. (iii) The four flurbiprofen pairs were kept on the basis of the superseded high absorption tier recorded in the design file at the 31 July 2026 lock (SHA-256 `8956cfe6…`), which predates the tier correction. Re-deriving the reference labels under the stated rule with the current registry tiers changes 10 of the 92 labels (`scripts/rederive_audit_gold.py`; result in `outputs/recomputed/audit_gold_rederived.json`); under those reference labels the cascade scores 61 of 92 (0.663) with high-risk sensitivity 8 of 29.

**LLM baseline parameters.** Ten-token setting: model identifier `deepseek-chat` via the OpenAI-compatible endpoint, `max_tokens` 10, no chain-of-thought prompt, temperatures 0.0, 0.3, 0.6, 0.9, 1.2 for conditions 0–4, one call per case, 118 + 92 + 200 + 70 cases per condition and method. The endpoint exposes neither parameter count nor checkpoint revision. Reasonable-budget re-run: `glm-5.3-flash` through the Zhipu coding-plan endpoint `https://open.bigmodel.cn/api/coding/paas/v4`, `max_tokens` 3000, temperature 0.0, five repeated samples per case, majority vote; reasoning tokens count against the budget because the model emits `reasoning_content` before `content`; reasoning effort was not set, so the endpoint default applied. No response was truncated (maximum completion 1,858 tokens) and no split vote arose (minimum modal agreement 3 of 5). The run produced 3,150 raw responses on 23–24 September 2026.

**Retrieval baseline parameters.** `naive_rag` uses `rank_bm25.BM25Okapi` with k1 = 1.5 and b = 0.75 over the same 1,307 chunks, lowercased and whitespace-tokenised; the query is `f"{a} {b} ophthalmic interaction"`, with `a` and `b` the ophthalmic and systemic drug names, so the query includes the drug names; the top-3 passages are retained (top-k = 3), each truncated to 400 characters, and prepended as an `Evidence:` block. `lightrag` prepends a `Drug profiles:` block rendered by `PreciseKG.full_kg_context()`, containing both agent profiles, the matched rule identifiers with severities, and — for low-absorption pairs with no matched rule — the instruction "Risk assessment MUST be 'low'". The blocks are prepended verbatim; no truncation is applied to the profiles.

**Parse rule.** Outputs were parsed by exact match first, then substring matching in the order high > medium/low, with an explicit `unknown` fallback. One of the 9,600 primary predictions (audit set, `naive_rag`, temperature 1.2) returned an unparseable string and was scored as `unknown`; all others parsed. In the reasoning-model re-run no sample returned `unknown`.

**Statistics.** Exact two-sided McNemar test on discordant case pairs at condition 0. Wilson score intervals for proportions, Clopper–Pearson intervals for subsets near the boundary, and nonparametric bootstrap intervals (2,000 resamples) for kappa. Standard deviations across temperature conditions are population SDs and describe the fixed temperature grid rather than sampling error. No power calculation was performed.

## Supplementary Text S10. Rule and matrix construction protocol

**Candidate generation.** Rules were generated from three sources: DDInter 2.0 pairs linking an ophthalmic agent to a systemic drug class; ophthalmic product labels (warnings and drug-interaction sections); and published case reports or reviews. Candidates were retained when the mechanism was explainable by an entity flag already present in the registry or could be added with a documented definition.

**Rule encoding and severity.** Each candidate was encoded as an entity-flag predicate with match-all or match-any semantics. Severity was assigned in a fixed order: the DDInter level where the pair was recorded; otherwise the label's warning category; otherwise the clinical consequence expected from the mechanism and the therapeutic index of the systemic drug. The support level of each severity is recorded in Table S9 as direct, inferred or provisional.

**Adjudication.** The rule inventory was reviewed by the study team and the two clinician authors; disagreements were resolved by consensus. There was no formal Delphi panel, blinded review or independent clinical committee. The only post-lock severity change was the dexamethasone CYP3A4 rule, downgraded from medium to low after the measured plasma concentration was found to be below 1 ng/mL.

**Class matrix.** The 21 ophthalmic row keys and 34 systemic column keys (33 with defined cells, drawn from the 40 systemic classes) were defined from the registry classes. 83 actionable cells were defined from the rule set, class extrapolation, expert consensus or pharmacological inference; 21 additional cells are explicitly marked none. Each cell records a level, mechanism, advice and evidence type (Table S14). Four upgrade rules require a class match plus a high-absorption or selectivity flag. Cell levels were reviewed with the rule set by the study team and were not independently adjudicated.

**Reproducibility.** The rule file, matrix file and their SHA-256 fingerprints are deposited. The rule-level audit is `data/curation/rule_provenance_audit.csv`; the matrix is `configs/class_matrix.yaml`.

**Supplementary Table S16. Source tiers A-E: what each can and cannot support.**

| Tier | Source type | What it can support | What it cannot support |
|---|---|---|---|
| A | Regulatory product label (FDA, EMA, NMPA) | Approved indications, labelled warnings, route-specific systemic-absorption statements and labelled interactions. | A negative statement is not proof of absence; labels are not systematic reviews. |
| B | Systematic review or meta-analysis | Pooled effect estimates for a defined question and population. | Often systemic-route only; may not address ophthalmic exposure or a specific pair. |
| C | Original clinical study or case report | A measured exposure, a reported event or a tested hypothesis. | Single studies may be underpowered, confounded or not generalisable. |
| D | In vitro, animal or pharmacokinetic first-principles evidence | Mechanistic plausibility, direction of an effect and approximate exposure. | Does not establish clinical severity or event probability in humans. |
| E | Class-level mechanism inference | A hypothesis for a pair with no direct source; used to flag, not to assert. | Cannot establish that the interaction occurs, its magnitude or its severity. |

The A-E tiers are a **source hierarchy**, not a strength-of-evidence grade. A label statement (A) can be less direct than a systematic review (B) for a specific pair, and an E-tier mechanism can be biologically plausible but unverified. The tiers describe provenance; they are not weights in the engine and do not enter the grade.

**Supplementary Table S17. Exposure-risk relationship by mechanism class.**

| Mechanism class | Exposure-risk relationship | Implication for interpretation | Example |
|---|---|---|---|
| Reversible pharmacodynamic antagonism or addition (beta-blockade, NSAID prostaglandin inhibition, alpha-2 agonism) | Roughly concentration-dependent, but the slope depends on receptor reserve, potency and therapeutic index. | Lower exposure usually lowers effect, but a potent agent or a narrow-therapeutic-index victim can still be clinically important. | Timolol + verapamil; ketorolac + warfarin |
| Narrow-therapeutic-index pharmacokinetic interaction (CYP induction/inhibition, P-gp) | Risk depends on the fractional change in victim-drug exposure, not on the ophthalmic agent's absolute exposure. | A small degree of inhibition can matter for warfarin, digoxin, tacrolimus or cyclosporine. | Dexamethasone + CYP3A4 substrates; beta-blocker + CYP2D6 inhibitors |
| Threshold or idiosyncratic reaction (sulfonamide hypersensitivity, fluoroquinolone tendon injury) | Not a simple linear function of exposure; host factors and prior sensitisation dominate. | Low exposure does not guarantee absence of risk; the grade should be read as a flag, not a probability. | Sulfacetamide; fluoroquinolones + systemic corticosteroid |
| Cumulative or time-dependent toxicity (corticosteroid IOP rise, adrenal suppression) | Depends on duration and cumulative dose, which the pair-level model does not represent. | A single-pair grade cannot capture long-term risk; duration must be assessed clinically. | Topical corticosteroid + systemic corticosteroid |

The absorption tier models **systemic exposure**, not **clinical interaction risk**. Reducing exposure reduces the probability of a concentration-dependent systemic effect, but it does not eliminate risk for narrow-therapeutic-index drugs, idiosyncratic reactions or cumulative toxicity. This is why the 77.7% divergence is reported as a difference in classification, not as evidence of reduced harm.
